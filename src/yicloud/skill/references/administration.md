# 项目、权限和配额变更

## 何时读取

用户明确要求管理项目、用户、权限、密钥策略、配额组或资源池时读取。仅查询账单或指标使用[观测手册](observability.md)。

## 变更流程

1. 明确操作对象、当前账号权限和用户要求的变化，列出受影响的项目或用户。不要把只读排错升级成权限修改。
2. 从 mc 或 iam 服务目录定位操作，读取现有配置；批量操作先取得并核对完整目标清单。
3. 查询目标 API 的 schema，构造只包含用户要求变化的有效请求，保留其他字段语义；完整替换接口需要带齐仍应保留的配置。
4. 按[API 手册](diagnostics/api.md)执行 dry-run；它不证明管理权限或后端业务条件满足。
5. 在当前授权范围内提交，再读取对象核对实际权限、策略或资源配置。

## 凭据类操作

CreateAccessKey 等接口可能返回一次性秘密，默认输出脱敏。确实需要交付新密钥时才使用根级 `--show-secrets`，并按用户指定的受信任渠道保存，不写入报告、仓库或 YICLOUD.md。

创建用户的密码通过受信任文件或 stdin 提供，不写入 shell 参数。新建密钥不自动授权删除旧密钥；用户只要求修改策略时不轮换凭据。

## 异常与完成标准

权限不足时报告受阻操作，不自动切换身份。写入结果未知时重读当前配置，不重发创建用户或密钥请求。删除用户、项目、配额组前明确依赖和用户意图，不自动级联清理。

交付说明对象、变更前后有效配置及读取验证结果，隐去秘密。接口返回成功但读取未确认时，明确尚未完成验收。
