# 用 rlaunch 调试开发机 Worker

适用于在已有开发机内启动短时调试 Worker，例如试跑训练入口、调试环境或检查资源。开发机停止、重启或异常关闭时，Worker 也可能被终止。需要独立生命周期的训练用[官方训练 CLI](../jobs/rjobv3.md)。具体限制见[官方 rlaunch 指南](https://docs.yicloud.com/6/2.html)。

## 确认开发机和资源

- 按[连接手册](connect.md)进入指定开发机，运行 `command -v rlaunch` 和 `rlaunch --help` 核对当前版本支持的参数。OpenAPI 调用前应显式设置 `YICLOUD_API_HOST`，从[平台域名信息](https://docs.yicloud.com/21/1.html)核对所属站点网关。沿用开发机的认证环境，`yicloud` 本地账号配置独立管理。
- 核对目标项目、计费资源组、区域与可用区。用 `--charged-group` 明确计费组。跨项目时先确认权限，并检查当前版本是否提供官方指南中的 `--namespace`。参数缺失或平台拒绝时，报告当前环境限制，避免把任务启动到别的项目。区域和可用区遵循当前版本的开发机继承规则。
- 资源可按 `--cpu`、`--gpu`、`--memory` 指定，内存按 MiB，或选用已确认的 `--sku-id` / `--sku-scope`。仅在目标资源组要求时设置私有机器或节点标签。需要预估可调度性时用 `--predict-only=true` 配合实际资源参数，预估无法保证随后调度成功。

## 选择运行模式

以下为短时单副本 CPU 调试示例。先填写已核实的 `$group`，资源和命令按实际调试需求调整。

```bash
rlaunch --charged-group="$group" --cpu=2 --gpu=0 --memory=4096 -- bash
```

- 交互模式保持终端连接并实时显示输出。退出或中断后检查 Worker 状态。
- 若需脱离终端，使用单副本 `-d`，并提供有限时长的命令。返回 Worker 名称后到控制台确认实际运行状态。

```bash
rlaunch --charged-group="$group" --cpu=2 --gpu=0 --memory=4096 \
  --enable-sshd -d -- sleep 600
```

- 多副本调试用 `-P`，当副本数大于 1 时不能与 `-d` 同用。检查各副本的启动命令、网络需求与重启策略。别把前台日志当成全部副本都已就绪的证据。

## 镜像、存储和 SSH

- 省略 `--image` 时按开发机环境的继承规则运行。需要独立镜像时填写已核实的可拉取镜像。使用 `--mount` 前确认来源和容器内路径，用 `--volume` 把开发机路径挂给镜像模式的 Worker 时核对版本与跨项目限制。需要保留的文件写入已验证的持久存储。
- 在目标开发机控制台的 Worker 列表按返回名称定位，查看调度状态、日志和资源用量。待 Worker 就绪并确认 SSH 服务可用后，从其详情页获取实际 SSH 命令。用 Worker 的地址、端口和身份，避免复用开发机本身的连接。
- 排队时先查资源组权限、剩余配额和节点是否满足请求。启动失败时检查镜像、挂载与日志。后台提交回显中断时先在 Worker 列表查找，按创建时间和配置核对，避免重复创建。调试结束后按授权在控制台清理指定 Worker。
