# 存储查询、挂载与持久化产物

## 何时读取

查询 GPFS 与容量配额、准备输入数据、设置挂载、传输文件、验证输出或清理存储时读取。

## 先确定存储类型与范围

沿用用户已选账号、项目、可用区及存储。区分本地文件、容器路径、GPFS 源、云盘和对象存储 URI；记录源到容器挂载点的映射，以及生产者、消费者身份。不能把主机路径直接当作容器路径，也不能假定创建者可读就意味着部署可读。

| 用户所指对象 | CLI 能力与边界 |
|---|---|
| GPFS 共享文件存储 | `fs` 查询可用集群、文件集及其容量、授权信息；文件集是管理对象，源 URI 和容器挂载点另行确认 |
| fileset / 文件集 | 不是文件上传接口，也不是任意路径目录；控制台的 filesets 名称不等于 CLI 服务名，当前入口为 `fs`，旧服务为 `fs/alpha` |
| 云盘、快照 | `volume` 管理块存储与快照；不代表容器已挂载、文件已复制或可跨实例共享 |
| 对象存储 / objectstores | 当前 CLI 的 `oss` 提供 bucket 管理；控制台名称不等于 CLI 命令，不能据此承诺对象上传、下载或通用文件 API |

已知映射直接核验；只在缺信息时查询对应类型。创建、扩容、共享授权、回收与删除的业务限制优先查[最新飞书说明](https://iqeubg8au73.feishu.cn/wiki/BG9Bwc6RliG4DbkIu2OckJKZnxh)的对应章节；无法读取时明确哪些政策未核实，不从本地 schema 推断当前平台政策或用写请求试探。

## GPFS：查询集群、文件集与容量

尚未确认可用集群或文件集时，分别按已确定的可用区、项目查询；两条命令按缺失信息选择，不是创建前必须全部执行：

```bash
yicloud --json fs list-available-gpfs-clusters --zone "$zone"
yicloud --json fs list-filesets-with-quota-info --project "$project" --zone "$zone" --all
```

核对实际返回的文件集标识、集群、项目、状态、容量使用与 Permission。列表若返回 `Capacity` / `Size`，分别为容量与已用字节；详情若返回 `Capacity` / `Used`，也按字节读取，不把字段缺失、null 或失败当作零。文件集容量配额与计算配额组不同；剩余额度不证明底层空间、inode 或本次写入一定足够。`PermFilter` 可缩小查询，但仍核对每个候选的实际权限，不把筛选条件当作权限证据。

需要某一文件集的详细容量、授权时，先从真实结果确认接口所需的文件集名称（列表可能以 `Bucket` 返回）与 `FsCluster`。执行前核对当前 CLI 是否接受该真实集群：固定 SDK 的部分请求仅接受 `gpfs1`，不支持目标值时先按[兼容问题](diagnostics/compatibility.md)核实合同，不能先发明知不兼容的请求。目标值被支持时才查询：

```bash
yicloud --json fs get-fileset --name "$fileset_name" --fs GPFS --fs-cluster "$fs_cluster"
```

这里的 Name 是接口要求的文件集名称，不能拿显示标签、Id 或路径代替。不改用 gpfs1、不省略集群让服务端猜选，也不以未知字段开关绕过枚举。列表无需预填集群即可发现候选；未知结构或详情失败时保留脱敏错误及请求 ID，不解释成不存在。

输入需要消费者读权限，输出需要消费者写权限。只按名称相似选择第一个、容量足够或列表可见，都不能确定目标及其权限。Source URI 从用户已确认的挂载来源、指定资源的真实挂载配置或控制台取得；目录 ID、名称和本地路径不能直接拼成 URI。已有完整 Source/Target 时无需重新枚举。缺少来源、目标或消费者权限时先补齐，查询候选不授权新建文件集、改权限或写入已有数据。

## 云盘与 bucket 查询

云盘按项目、可用区列出；已知实际云盘 ID 时直接查询详情，无需先列表：

```bash
yicloud --json volume list-volumes --project "$project" --zone "$zone" --all
yicloud --json volume get-volume --project "$project" --zone "$zone" --volume-id "$volume_id"
```

`volume_id` 来自用户指定或真实列表，不是显示名称；核对返回的 `Id`、`Namespace`、`ZoneId`、容量、状态及 `MountReference`。CLI 的 `--all` 是读取全部分页，API 的 `All` 字段对应 `--field-all`，不能混用。只查数据盘可按任务增加 `--type '["data"]'`，查回收站可显式增加 `--soft-deleted true`；查询失败不代表没有云盘。

Bucket 用任务已给的项目名、桶名或所有者关键词缩小查询；已知精确桶名时直接获取详情：

```bash
yicloud --json oss list-buckets --keyword "$bucket_keyword" --all
yicloud --json oss get-bucket --bucket "$bucket_name"
```

这两个接口没有 `--project` / `--zone` 参数，context 不会补入项目筛选；Keyword 是搜索条件，仍须核对返回的 `Bucket`、`Project`、`Permission` 与状态，不能将搜索命中视为项目隔离或对象读写授权。云盘和 bucket 的其他操作按需用 `api list --service volume` / `oss` 定位，不从管理对象存在推断文件或对象可读。

## 挂载与传输

Workspace 的 GPFS 挂载请求见[开发机创建](workspace/create.md)，Job 各角色的挂载请求见[训练执行](jobs/run.md)；请求结构以对应创建手册为准。新建与挂载是两步，文件集创建成功不等于已挂载。不要因使用 GPFS 自动替换用户选择的云盘，也不要给未要求持久化的任务自动创建存储。

### 多台机器共用同一目录

目标资源可访问同一 GPFS 集群、且各消费者具备相应权限时，同一个 GPFS 目录可以同时挂载给多台开发机、多个 Job 及其所需角色和副本，共用同一份文件。复用已确认的 Source；各容器的 Target 可以不同，代码使用各自 Target 下的路径。相同 Target 配不同 Source 不代表共享，不默认支持任意跨项目或跨可用区挂载。

常见流程是联网 CPU 机器将数据、权重或离线依赖写入共享目录，H200 资源读取同一来源，避免逐机复制；联网与依赖兼容要求见[环境准备](environment.md)。并发读取可共用输入，输出宜按任务或实例分目录；修改和删除共享文件会影响其他消费者，同一文件的并发写入须由应用协调，不能把共享挂载当作并发写安全保证。

### 核对与传输

- 连接开发机或 Job 实例后，在实际消费者身份下核对挂载点、源、工作目录和权限；连接方法见[连接与远程操作](workspace/connect.md)。目标目录存在或 `test -w` 通过不足以证明挂载正确、写入成功。
- 开发机传输用 [workspace scp](workspace/connect.md)，复制后检查实际目标文件；相对路径依赖远端工作目录，持久化输出应使用已确认的挂载内路径。
- 对象传输使用已配置的 S3 兼容客户端。先核实 endpoint、bucket、对象 key 和独立 S3 身份，不把网关 HMAC 凭据当作 S3 凭据。

若使用已安装并配置好的 AWS CLI，下例变量分别来自真实 endpoint、源文件及对象 URI；属于上传操作，须在任务范围内：

```bash
aws --endpoint-url "$s3_endpoint" s3 cp "$source_file" "$object_uri"
```

凭据不写入命令或项目资产文档；目标已存在时先确认覆盖属于任务范围。

`fs list-dir` 与 `fs get-file-info` 可查询接口支持的路径信息，但 Path 必须来自已确认的接口路径合同，不能直接套用本地或容器路径。只查询任务指定目录，避免递归扫描研究内容；这些元数据接口不证明文件内容已传输。旧 `fs/alpha` 的文件操作也不代表当前 GPFS、云盘和对象存储都支持同一种文件 API。

## 读写与持久化验收

1. 从生产任务配置取得精确输出路径，不只采用日志中未经检查的描述。
2. 在目标消费环境实际读取任务指定的输入或产物；检查用户要求的内容、格式、数量或哈希。元数据可见、挂载配置存在、dry-run 通过或任务 Succeeded 均不代替实际读取。
3. 需要验证写权限时，仅在用户已选且授权写入的目录中，用本次唯一名称排他创建小型测试文件，实际写入、关闭后读回并核对。不要覆盖同名文件或借测试修改授权；没有写入授权时报告写权限未实测。
4. 要求持久化或跨任务共享时，由独立后续进程，必要时另一指定消费资源，读取同一已知产物并核对；不能只验证生产者自身的临时文件系统。
5. 清理只删除本次创建且可确认归属的测试文件及空目录；不递归删除研究目录。删除 Workspace / Job 不证明这些存储文件已清除。

没有产物时先检查挂载、运行目录、消费者权限、配额与任务日志并保存必要证据；没有清理约定时保留排错资源，已有明确清理约定时记录取证或验证缺口后执行已授权清理，不扩大到用户既有数据。训练任务的取证方式见[失败取证](jobs/observe.md#失败取证)。

## 管理变更、清理与异常

创建文件集、修改容量配额、授权或删除时，先明确目标、当前值、期望值、依赖及授权范围，并核实最新平台限制。按目标用 `api describe fs ACTION` 查询 `CreateFilesetWithQuota`、`SetFilesetQuota`、`UpdateFileset` 或 `DeleteFileset`，再构造完整请求并 dry-run；不能从操作名推断支持缩容或某种共享范围。dry-run 仅本地校验，不检查业务权限、剩余配额或实际容量。

执行后重新读取目标详情与容量/授权，按任务验收消费者访问；写入结果未知时先查状态，避免重复创建或变更。删除前核对唯一标识和依赖，不根据名称相似删除文件集或目录。

固定 SDK 将开发机的 DelWithCloudVolume=true 描述为关联云盘进入回收流程，不是当前线上回收政策或物理销毁承诺。SoftDeleted、DeleteTime 或列表过滤不一致时，结合详情、回收站与最新说明核对，不凭单个字段宣称删除完成。

`fs/alpha` 是旧文件存储 API 服务名；通过 CLI 路由调用，不自行拼 URL。未知列表结构不能当作空目录，协议差异见[兼容问题](diagnostics/compatibility.md)。

完成时报告真实映射、容量与权限查询结论、消费者读写证据及清理范围。分别说明本地校验、真实元数据查询和真实文件读写的结果与未验证项；管理接口成功不代表文件上传或内容验证完成。
