# 提交与运行训练

## 何时读取

用户要求提交或执行训练任务时读取。已有任务的日志、产物和结束处理见[观察手册](observe.md)。

## 准备请求

先区分用户要“提交任务”还是“运行完成并取得产物”。确定项目、可用区、名称、真实镜像、启动命令、资源模式与输入输出路径；用户指定框架与脚本时沿用，不重写研究方法。

- 简单单角色任务：查 `job create --help`，使用真实值填写快捷参数。默认单副本、角色 t0、`sh -c`；镜像必须有 sh。仅明确需要登录初始化时使用 `--login-shell`。
- 多角色、挂载或完整启动参数：查询 `api describe job CreateJob`，保存完整 JSON。TaskSpecs 是角色名映射，不是数组；请求文件不补 context，也不能和快捷参数混用。
- SKU 与配额模式二选一。CPU 配额快捷创建省略 GPU 时发送 0；完整文件按真实需要显式填写 GPU，不能假定相同默认值。
- 私有资源选择、QoS、优先级仅按用户要求与实际资源组填写。它们省略时交给平台，不将一次测试配置变成全局默认。
- 用户要求限制排队或运行时间时，可用 `--max-wait-duration` / `--max-running-duration`（正整数 s/m/h/d）。它们是远端任务时限，区别于本地 `wait --timeout`。

使用持久输出路径时，先按[存储手册](../storage.md)确认挂载和消费者权限。离线环境按[环境准备](../environment.md)准备，避免运行时隐式公网下载。

## 确认启动依赖

启动命令中的解释器、脚本和必要程序必须与目标镜像及挂载匹配。本机安装了 Python、镜像标签包含 Python 版本或 dry-run 通过，都不能证明容器内存在 `python` 命令。

- 有已确认的同镜像运行环境时，在该环境检查 `command -v python`、`command -v python3` 及所需脚本是否可读。使用实际存在且满足依赖要求的解释器；虚拟环境优先使用已确认的解释器绝对路径。
- 无法提前进入目标环境时，可在已授权的任务入口加入最小依赖检查，缺失时输出具体程序或路径并退出；不要为检查擅自新建开发机，也不要把尚未检查的条件报告为通过。
- 用户明确指定解释器时沿用，不静默将 `python` 改成 `python3`，不自动安装依赖或建立全局软链接。只有根据真实环境和用户意图确认等价后才修正命令。

## 校验与提交

`request_file` 必须是已填写真实值的完整请求；简单任务也可对原快捷命令使用相同的校验与提交顺序。

```bash
yicloud job create --file "$request_file" --dry-run
```

检查预览中的名称、范围、资源和启动命令。校验失败时仅修正有依据的字段问题；成功后在授权范围内执行相同命令并移除 `--dry-run`。

保存真实 JobId。查询 `job status "$job_id"` 确认资源可见；用户只要求提交时，可报告平台已接受以及当前状态。

用户要求运行结果时：

1. 执行 `job wait "$job_id"` 观察至成功终态。排队超过本地等待时限不能报告任务失败，也不能自动换资源或重复提交。
2. 用 `job logs "$job_id" --start "$started_at"` 查询覆盖本次运行的日志；started_at 是实际启动时间，使用带时区 RFC3339。核对主程序退出与任务目标，不把初始化警告自动当成训练失败。
3. 从请求中声明的输出位置读取实际文件或对象，检查用户要求的格式、内容或哈希。日志标记与 Succeeded 不能代替文件验证。
4. 要求持久化时从后续消费环境读取同一产物。需要特定存储传输方式再读存储手册；文件缺失则保留资源并进入观察手册排错。

## 异常处理

- 创建响应超时或被中断：先按原名称、项目、可用区查询。零条时考虑可见延迟，不能立即重发；一条时核对创建时间、镜像、命令及可用请求关联证据，不能冒认旧任务；多条时停止并消歧。证据不足仍报告结果未知。
- 平台拒绝：保留错误码、request_id 和 hints；不要循环猜参数。尤其不能为避开错误而擅自改变重试策略。
- 请求中明确的字段被本地枚举拒绝：读[兼容问题](../diagnostics/compatibility.md)，不要换成看似接近的值。
- 启动或运行失败：先保存本次任务状态、日志和副本详情，再按[观察手册](observe.md)诊断或清理；不自动删除重建。遇到退出码 127，结合原始日志核对无法找到的是哪个程序，不只凭退出码推断缺少 Python。

## 完成标准

提交目标需要真实 JobId 和已查询状态；运行目标需要任务终态；产物目标还需要真实内容验证。报告实际达到的层次，任务停止、删除或环境释放仅按用户要求执行。
