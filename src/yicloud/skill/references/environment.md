# 离线依赖与环境镜像

## 何时读取

目标任务缺少依赖、无法公网下载，或需要制作可复用环境镜像时读取。先复用用户已有环境，不为普通查询创建准备机。

## 选择准备方式

| 条件 | 处理 |
|---|---|
| 目标可访问已确认的内部源 | 在目标环境验证必要依赖，按任务需要固化镜像 |
| 需要公网文件或内部源缺包 | 在已确认可联网的 CPU 环境下载，通过共享存储交付 |
| 需要从镜像归档提取环境 | 在支持 Docker 的 CPU 环境提取，再到真实目标验证 |

H200 按默认无公网准备；其他资源以当前配置为准，不假定可联网。内网可达与公网可达分别检查。具体包源地址只从当前项目 YICLOUD.md、用户或管理员提供的信息取得，不从其他平台猜测。

## 准备与固化

1. 核对目标 CPU 架构、Linux 发行版、Python ABI、CUDA 与框架要求，选择匹配依赖。CPU 上安装成功不证明 GPU 可运行，也不应因此安装 CPU-only 框架。
2. 代码、权重和数据放在实际消费者可读的存储；镜像保存运行环境。核对启动时是否仍会隐式下载。
3. 制作开发机镜像前，读取进程列表取得真实 ProcessId，查询 GetReleaseExcludePatterns 与 ReleaseProcess 的请求定义。WorkspaceId 或系统 PID 不能替代 ProcessId。
4. 检查打包范围，排除凭据、SSH 私钥和临时认证文件；不要假定挂载盘或虚拟环境自动进入镜像。
5. 使用真实镜像仓库与新版本标签，dry-run 后提交制作请求，再查询镜像实际存在且消费项目可见。
6. 在目标 GPU 验证依赖导入、设备识别和最小运算，再报告迁移成功；此前保留可复现构建记录或必要准备环境。

ReleaseProcess 不接受 Project；不要为了与其他请求一致而补字段。请求提交成功不等于镜像已完成制作。

## 内部源与离线包

使用 Dependency Gateway 时，先按管理员提供的指引查询 `/healthz` 与 `/v1/status` 并确认本次源启用；它不是任意公网代理，不预置私有地址。下载成功可能是 BYPASS，不代表内容已缓存，离线交付需要实际验证缓存或本地依赖完整性。Ubuntu 源必须匹配发行版，保留签名和 TLS 校验，不全局关闭验证。

离线下载包含匹配平台的依赖闭包，不只复制单个 wheel/deb。macOS 安装包不能用于 Linux。提取镜像环境还需核对动态库和硬编码路径，仅复制 `/usr/local` 不保证兼容。

GPU 环境若拒绝 Docker/unshare，不尝试提权绕过；将需要 Docker 的提取放在支持它的 CPU 环境。临时容器完成提取后只清理自己创建的对象。

## 异常与完成标准

源不可达或缺包时改为已授权的离线准备路径，不在任务启动时反复尝试公网。完成时提供固定镜像版本或依赖清单、存储位置、目标验证结果与残留限制；CPU 上的检查不能替代 GPU 验证。
