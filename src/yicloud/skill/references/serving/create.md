# 创建推理部署

## 何时读取

用户要求创建或上线持续运行的模型推理服务时读取。训练任务使用 Job；普通容器应用使用[应用托管](../applications.md)。

## 确定部署方式与参数

先从用户意图、已有配置或实际平台资产确定部署模式和模型版本，再查 `api describe inferset CreateInferSet`。它是固定 SDK 请求结构，不会替用户选择部署方式。

| 信息 | 来源与检查 |
|---|---|
| 项目、可用区、名称 | 用户指定或现有 context；完整文件必须实际填入 |
| 模型及版本 | 用户选定或平台可见资产，固定版本和真实存储位置 |
| 引擎、镜像、启动命令 | 对应模式的已有配置；快速部署由平台预置时不强求自定义值 |
| 资源和副本 | 用户要求与真实规格；按当前模式校验，不套用训练 TaskSpecs |
| 端口、探针、访问范围 | 该模式要求的实际配置，不能擅自开放公网 |
| 挂载与拓扑 | 已验证的存储及模式配置，PD 分离、多机和 KV Cache 不套用单机模板 |

只补问当前模式必需且无法从上下文取得的信息。schema 中可选不代表业务可省略；模式缺少可靠字段依据时停止构造，不自行发明拓扑。

## 准备与校验

将确认后的完整结构保存为请求 JSON，检查路径、端口与启动命令一致，模型消费者有读取权限，副本与拓扑匹配。没有可直接部署的通用默认模板。

```bash
yicloud serving create --file "$request_file" --dry-run
```

校验失败时修正有依据的字段，再次校验；结果不明确时不提交。通过只说明请求符合本地合同，不能保证镜像可拉取或当前有算力。

## 创建与验证

1. 当前授权覆盖创建且校验通过后，对同一请求移除 `--dry-run` 执行。
2. 保存返回的真实 ID，不能用 Name 代替。创建结果没有可靠 ID 时先查询目标范围确认，不立即重建。
3. 查询 `serving status "$serving_id"`，需要等待运行状态时执行 `serving wait "$serving_id"`。
4. 查询 `serving instances "$serving_id"`；普通单机副本需要精确验收时按[扩缩容手册](scaling.md)等待目标副本。
5. 用户要求服务可调用时，从真实部署配置取得端点、协议和认证方式，在授权范围内发最小推理请求，检查响应。缺少调用条件时报告未验证，不猜路径、密钥或请求体。

## 异常与完成标准

- 请求超时：按原名称、项目、可用区查询是否创建，不重复提交。
- 未就绪：检查状态、实例和[历史日志](logs.md)，不自动删除重建。
- 状态未知或响应不符：保留原始值，读[兼容问题](../diagnostics/compatibility.md)，不宣称 Running 或健康。

报告名称、ID、项目、可用区、请求文件位置，以及分别验证到的 API 接受、部署状态、实例就绪和推理调用结果。用户只要求创建时不额外执行未经授权的业务调用。
